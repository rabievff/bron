# Бронирование кабинетов офиса

Консольная утилита для бронирования пяти переговорных кабинетов:
проверяет, свободен ли кабинет в заданное время, позволяет его
забронировать и отправляет сотруднику письмо с датой, временем и
номером кабинета.

Написана **без фреймворков** — только стандартная библиотека Python:
`sqlite3` (СУБД), `smtplib` (почта), `argparse` (CLI), `unittest`
(тесты). Сторонних зависимостей нет.

## Требования

- Python 3.9 или новее;
- SMTP-сервер — опционально: пока он не настроен, письма печатаются в
  консоль, и утилита полностью работоспособна.

## Быстрый старт

```bash
git clone <адрес-репозитория>
cd bron
python -m booking init
```

Команда `init` создаёт файл `office.db` и заполняет справочник из пяти
кабинетов: Альфа, Бета, Гамма, Дельта, Омега.

## Команды

| Команда  | Назначение                                              |
|----------|---------------------------------------------------------|
| `init`   | создать базу данных и справочник кабинетов              |
| `rooms`  | показать список кабинетов                               |
| `check`  | проверить занятость и предложить бронирование           |
| `book`   | забронировать кабинет                                   |
| `notify` | отправить письмо владельцу брони                        |
| `list`   | показать расписание броней                              |
| `cancel` | отменить бронь                                          |

### Проверка занятости

Без `--room` проверяются сразу все пять кабинетов:

```bash
python -m booking check --date 2026-08-11 --from 11:00 --to 12:00
```

```
Проверка на 11.08.2026 11:00-12:00
--------------------------------------------------------------
  [СВОБОДЕН]  Кабинет №1 «Альфа»
  [СВОБОДЕН]  Кабинет №2 «Бета»
  [ЗАНЯТ]     Кабинет №3 «Гамма» — освободится в 12:30
      занято до 11:30 — Иван Петров <ivan@example.com>, тема: Планёрка [10:00-11:30, бронь №1]
      занято до 12:30 — Мария Сидорова <maria@example.com> [11:30-12:30, бронь №2]
  [СВОБОДЕН]  Кабинет №4 «Дельта»
  [СВОБОДЕН]  Кабинет №5 «Омега»
--------------------------------------------------------------
Свободны: №1, №2, №4, №5

Забронировать кабинет? Номер [1] или Enter для выхода:
```

Если есть свободные кабинеты, команда предлагает забронировать один из
них прямо в диалоге и спрашивает имя, e-mail и тему встречи. Флаг
`--no-input` отключает диалог — удобно для скриптов.

### Бронирование

```bash
python -m booking book --room 3 --date 2026-08-11 --from 10:00 --to 11:30 \
    --name "Иван Петров" --email ivan@example.com --purpose "Планёрка"
```

Если кабинет занят, выводится, кем и до скольки:

```
Кабинет №3 «Гамма» занят на это время:
  занято до 11:30 — Иван Петров <ivan@example.com> [10:00-11:30]
```

### Уведомление на e-mail

Отдельная команда — отправляет владельцу брони письмо с датой, временем
и номером кабинета:

```bash
python -m booking notify 1
```

Флаг `--dry-run` показывает письмо, ничего не отправляя. Тот же результат
можно получить сразу при бронировании — флагом `--notify` у команды
`book`. После успешной отправки в базе проставляется `notified_at`.

### Расписание и отмена

```bash
python -m booking list --date 2026-08-11
python -m booking list --room 3 --all
python -m booking cancel 1
```

### Сокращённые флаги

`-r` — кабинет, `-d` — дата, `-f` — начало, `-t` — конец, `-n` — имя,
`-e` — почта, `-p` — тема. Дата принимается в форматах `2026-08-11`,
`11.08.2026`, а также словами `сегодня` и `завтра`:

```bash
python -m booking check -d завтра -f 10:00 -t 11:30
```

## Настройка почты

Скопируйте `.env.example` в `.env` и заполните параметры SMTP:

```bash
cp .env.example .env
```

Пока `SMTP_HOST` пуст, используется вывод в консоль вместо отправки.
Файл `.env` внесён в `.gitignore`, пароли в репозиторий не попадают.
Для Gmail нужен пароль приложения, а не основной пароль аккаунта.

## Устройство проекта

```
booking/
├── cli.py          интерфейс командной строки (argparse)
├── service.py      бизнес-логика: проверка, бронирование, отмена
├── repository.py   SQL-запросы
├── db.py           подключение к SQLite, схема, транзакции
├── models.py       модели Room и Booking
├── notifier.py     формирование и отправка писем (smtplib)
├── slots.py        разбор дат и времени, пересечение интервалов
├── config.py       настройки из окружения и .env
└── errors.py       доменные исключения
```

Слои разделены: `cli` не знает о SQL, `service` не знает о выводе в
консоль, весь SQL собран в `repository` и `db`. Замена SQLite на
PostgreSQL затронет только эти два модуля.

### Схема базы данных

```sql
rooms    (id, name, capacity)
bookings (id, room_id → rooms.id, person_name, person_email,
          starts_at, ends_at, purpose, created_at, notified_at)
```

Время хранится строками `ГГГГ-ММ-ДД ЧЧ:ММ:СС` — такой формат
сортируется лексикографически, поэтому сравнения работают штатными
средствами SQLite без дополнительных преобразований.

### Как определяется занятость

Интервалы полуоткрытые — `[начало, конец)`. Две брони конфликтуют,
если `начало_A < конец_B И конец_A > начало_B`. Благодаря этому брони
10:00–11:00 и 11:00–12:00 не считаются пересекающимися: кабинет
освобождается ровно в момент окончания предыдущей встречи.

Проверка занятости и вставка выполняются в одной транзакции
`BEGIN IMMEDIATE`. Без неё два одновременных запуска могли бы оба
пройти проверку и занять один интервал.

## Коды возврата

| Код | Значение                            |
|-----|-------------------------------------|
| 0   | успех                               |
| 1   | ошибка ввода или доменная ошибка    |
| 2   | кабинет занят                       |

Код `2` позволяет проверять занятость из скриптов:

```bash
python -m booking check -r 3 -d завтра -f 10:00 -t 11:00 --no-input || echo "занято"
```
