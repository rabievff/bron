# Бронирование кабинетов офиса

Консольная утилита для бронирования пяти переговорных кабинетов:
проверяет, свободен ли кабинет в заданное время, позволяет его
забронировать и отправляет сотруднику письмо с датой, временем и
номером кабинета.

Написана на **Go без фреймворков**: CLI на пакете `flag`, почта на
`net/smtp`, работа с СУБД через `database/sql` — всё из стандартной
библиотеки.

## Единственная зависимость

`modernc.org/sqlite` — драйвер SQLite.

Обойтись без него нельзя: стандартная библиотека Go предоставляет
только интерфейс `database/sql`, а драйверов СУБД в ней нет ни для
SQLite, ни для PostgreSQL, ни для MySQL. Это драйвер базы, а не
фреймворк — вся логика, интерфейс и почта остаются на stdlib.

Выбран именно этот драйвер, а не более известный `mattn/go-sqlite3`,
потому что он написан на чистом Go: не требует cgo и установленного
компилятора C, поэтому собирается на Windows «из коробки».

## Требования

- Go 1.23 или новее;
- SMTP-сервер — опционально: пока он не настроен, письма печатаются в
  консоль, и утилита полностью работоспособна.

## Быстрый старт

```bash
git clone https://github.com/rabievff/bron.git
cd bron
go build -o booking ./cmd/booking
./booking init
```

На Windows:

```bash
go build -o booking.exe ./cmd/booking
```

Команда `init` создаёт файл `office.db` и заполняет справочник из пяти
кабинетов: Альфа, Бета, Гамма, Дельта, Омега.

Можно запускать и без сборки:

```bash
go run ./cmd/booking check -d завтра -f 10:00 -t 11:30
```

## Команды

| Команда  | Назначение                                       |
|----------|--------------------------------------------------|
| `init`   | создать базу данных и справочник кабинетов       |
| `rooms`  | показать список кабинетов                        |
| `check`  | проверить занятость и предложить бронирование    |
| `book`   | забронировать кабинет                            |
| `notify` | отправить письмо владельцу брони                 |
| `list`   | показать расписание броней                       |
| `cancel` | отменить бронь                                   |

### Проверка занятости

Без `-r` проверяются сразу все пять кабинетов:

```bash
./booking check -d 2026-08-11 -f 11:00 -t 12:00
```

```
Проверка на 11.08.2026 11:00-12:00
--------------------------------------------------------------
  [СВОБОДЕН]  Кабинет №1 «Альфа»
  [СВОБОДЕН]  Кабинет №2 «Бета»
  [ЗАНЯТ]     Кабинет №3 «Гамма» — освободится в 12:30
      занято до 11:30 — Иван Петров <ivan@example.com>, тема: Планёрка [10:00-11:30, бронь №1]
      занято до 12:30 — Мария Сидорова <maria@example.com> [11:30-12:30, бронь №2]
  [СВОБОДЕН]  Кабинет №4 «Дельта»
  [СВОБОДЕН]  Кабинет №5 «Омега»
--------------------------------------------------------------
Свободны: №1, №2, №4, №5

Забронировать кабинет? Номер [1] или Enter для выхода:
```

Если есть свободные кабинеты, команда предлагает забронировать один из
них прямо в диалоге и спрашивает имя, e-mail и тему встречи. Флаг
`-no-input` отключает диалог — удобно для скриптов.

### Бронирование

```bash
./booking book -r 3 -d 2026-08-11 -f 10:00 -t 11:30 \
    -n "Иван Петров" -e ivan@example.com -p "Планёрка"
```

Если кабинет занят, выводится, кем и до скольки:

```
Кабинет №3 «Гамма» занят на это время:
  занято до 11:30 — Иван Петров <ivan@example.com> [10:00-11:30]
```

### Уведомление на e-mail

Отдельная команда — отправляет владельцу брони письмо с датой, временем
и номером кабинета:

```bash
./booking notify 1
```

Флаг `-dry-run` показывает письмо, ничего не отправляя. Тот же результат
можно получить сразу при бронировании — флагом `-notify` у команды
`book`. После успешной отправки в базе проставляется `notified_at`.

### Расписание и отмена

```bash
./booking list -d 2026-08-11
./booking list -r 3 -all
./booking cancel 1
```

### Флаги

`-r` кабинет, `-d` дата, `-f` начало, `-t` конец, `-n` имя, `-e` почта,
`-p` тема. У каждого есть длинная форма: `-room`, `-date`, `-from`,
`-to`, `-name`, `-email`, `-purpose`.

Дата принимается в форматах `2026-08-11`, `11.08.2026`, а также словами
`сегодня` и `завтра`:

```bash
./booking check -d завтра -f 10:00 -t 11:30
```

Справка по команде: `./booking book -h`.

## Настройка почты

Скопируйте `.env.example` в `.env` и заполните параметры SMTP:

```bash
cp .env.example .env
```

Пока `SMTP_HOST` пуст, используется вывод в консоль вместо отправки.
Файл `.env` внесён в `.gitignore`, пароли в репозиторий не попадают.
Для Gmail нужен пароль приложения, а не основной пароль аккаунта.

## Устройство проекта

```
cmd/booking/main.go          точка входа
internal/booking/
├── cli.go        интерфейс командной строки (flag)
├── service.go    бизнес-логика: проверка, бронирование, отмена
├── store.go      СУБД: схема, транзакции, весь SQL
├── model.go      Room, Booking, Availability
├── notifier.go   формирование и отправка писем (net/smtp)
├── slot.go       разбор дат и времени, пересечение интервалов
├── config.go     настройки из окружения и .env
└── errors.go     доменные ошибки
```

Слои разделены: `cli` не знает о SQL, `service` не знает о выводе в
консоль, весь SQL собран в `store.go`. Замена SQLite на PostgreSQL
затронет только этот файл.

### Схема базы данных

```sql
rooms    (id, name, capacity)
bookings (id, room_id → rooms.id, person_name, person_email,
          starts_at, ends_at, purpose, created_at, notified_at)
```

Время хранится строками `ГГГГ-ММ-ДД ЧЧ:ММ:СС` — такой формат
сортируется лексикографически, поэтому сравнения работают штатными
средствами SQLite без дополнительных преобразований.

### Как определяется занятость

Интервалы полуоткрытые — `[начало, конец)`. Две брони конфликтуют,
если `начало_A < конец_B И конец_A > начало_B`. Благодаря этому брони
10:00–11:00 и 11:00–12:00 не считаются пересекающимися: кабинет
освобождается ровно в момент окончания предыдущей встречи.

Проверка занятости и вставка выполняются в одной транзакции, а строка
подключения содержит `_txlock=immediate` — блокировка на запись берётся
сразу. Без этого два одновременных запуска могли бы оба пройти проверку
и занять один интервал.

## Коды возврата

| Код | Значение                         |
|-----|----------------------------------|
| 0   | успех                            |
| 1   | ошибка ввода или доменная ошибка |
| 2   | кабинет занят                    |

Код `2` позволяет проверять занятость из скриптов:

```bash
./booking check -r 3 -d завтра -f 10:00 -t 11:00 -no-input || echo "занято"
```

## Качество кода

Проект соответствует стандартным соглашениям Go:

- форматирование `gofmt` — проверяется командой `gofmt -l .`;
- статический анализ `go vet ./...` проходит без замечаний;
- документирующие комментарии у всех экспортированных типов и функций;
- ошибки оборачиваются через `%w` и проверяются `errors.Is`/`errors.As`.

```bash
gofmt -l . && go vet ./...
```
